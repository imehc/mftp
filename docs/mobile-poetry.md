# 移动端古诗词与 AI 翻译实施计划

状态：实施中（M1 已完成，M2 移动独立下载已完成主要代码，真机验证待完成）。

日期：2026-09-19。

本文只描述移动端适配计划，不替代 `docs/library.md` 的文库总体设计，也不修改
`docs/ai.md` 已确定的统一 AI 安全边界。

## 1. 目标

在 iOS 和 Android 提供适合触屏与单栏导航的古诗词体验，并复用已经实现的 AI
翻译能力。

首版必须支持：

- 从首页进入古诗词。
- 浏览、搜索、合集筛选、每日一诗和随机阅读。
- 列表进入独立详情页，返回后恢复查询条件与滚动位置。
- 阅读正文、作者信息、上游注释以及已安装的开放译文。
- 配置用户自己的 AI 服务，按需生成白话直译或文学意译。
- 查看流式生成过程，编辑、删除和重新生成译文。
- 离线读取已经安装的诗词数据和已经保存的译文。
- 明确展示下载体积、磁盘占用、生成状态和失败状态。

## 2. 非目标

以下内容不进入移动端范围：

- 自动或批量生成 AI 译文；AI 翻译始终是单篇、用户主动触发。
- 从本地文件导入注释包或翻译包。
- 面向用户提供任意格式的数据包导入入口。
- 内置 API Key、默认付费 AI 服务或任意提示词聊天入口。

以下内容不阻塞移动端首版，可在后续阶段单独评估：

- 移动端后台持续下载或系统级后台任务。
- 在手机上下载并解析完整 `chinese-poetry` 上游仓库。
- 默认安装全宋诗等大体量合集。
- 移动端朗诵音频缓存。
- 首版支持注释包在线安装和完整数据管理能力。
- 修改桌面端现有双栏交互。

## 3. 当前基础与差距

### 3.1 已可复用

- Rust 端的诗词 SQLite schema、导入、查询、全文检索、每日一诗和随机阅读已经实现。
- 诗词查询和 AI 翻译 IPC 已注册在全平台命令列表，不需要新增一套移动端协议。
- `/library/$id` 已有独立详情页面，可作为移动端详情路由。
- AI 译文已经支持生成、流式增量、保存、人工修订、删除和重新生成。
- AI 配置保存在主库，译文不会随可重建的 `poetry.sqlite3` 一起被删除。
- iOS 使用系统 Keychain，Android 使用 Android Keystore 保存 API Key。
- AI 网络请求由 Rust 执行，前端不接触 API Key，也不依赖 WebView CORS。
- 页面壳和全局样式已经处理 safe-area，可继续复用。

### 3.2 当前阻塞点

- 首页古诗词入口带有 `platforms: ["desktop"]`。
- `/library`、`/library/$id` 和 `/library/manage` 都使用 `desktopOnlyGuard`。
- `LibraryPage` 以 `react-resizable-panels` 双栏布局为核心，没有移动端单栏流程。
- 桌面端支持完整上游 tar.gz 回退和本地导入；移动端必须独立完成网络下载。
- 移动端需要低峰值磁盘占用的数据首次安装方案。
- 设置页在移动端隐藏 `AiConnectionSettings`，导致后端虽可用但用户无法配置。
- 数据管理页信息密度和操作流程按桌面设计，不能直接在小屏照搬。

## 4. 核心决策

### D1：移动端使用单栏路由，桌面保留双栏

- `/library` 在移动端只展示发现、搜索、筛选和结果列表。
- 点击作品导航到 `/library/$id`，不在列表页内展开详情。
- 详情页使用系统式返回流程；返回时保留 `q`、筛选条件和列表滚动锚点。
- 桌面端继续使用当前 master-detail 双栏，不因移动端适配退化。
- 手机和平板均遵循移动端导航语义；具体密度再按 viewport 响应式增强。

### D2：移动端只下载精选源文件，不回退完整归档

桌面和移动端共用 GitHub tree/blob API：先读取源仓库 tree，再按目录和合集规则筛选
所需文件，逐个下载到应用临时目录后复用现有解析和事务导入。这样移动端只传输当前
选择所需的数据，避免完整仓库归档带来的临时磁盘峰值。

- 桌面端在 tree/blob 请求失败或 API 额度不足时仍可回退上游 tar.gz。
- 移动端不请求 codeload，也不下载完整 tar.gz；精选文件下载无法继续时直接报错，
  用户可重试。
- 下载、导入和清理沿用现有进度事件、取消逻辑、uid 规则和数据库事务，不建立移动端
  专用数据格式或 Release 数据资产。
- 首版仍提供精选合集，不默认安装全宋诗；扩展合集由用户显式选择。

建议首版精选合集包含唐诗三百首、诗经、楚辞、花间集、纳兰性德、幽梦影、南唐二主词
和曹操诗集。全唐诗、宋词、元曲作为用户显式选择的扩展合集。

### D3：下载仅承诺前台完成

- 下载和导入期间明确显示“请保持应用开启”。
- 应用进入后台时允许系统暂停，不承诺继续运行。
- 回到前台后根据临时文件状态恢复或安全重试。
- 不为了首版引入 iOS BackgroundTasks 或 Android WorkManager。
- 取消、失败和应用重启都必须有临时资源清理路径。

### D4：AI 翻译继续采用 BYOK

- 用户配置服务地址、模型和 API Key 后才能生成。
- 只支持现有 OpenAI Responses 接口格式。
- 每次生成必须由用户在单篇详情中主动点击触发，不自动翻译、不提供批量入口。
- 发送前沿用任务输入白名单，仅发送生成该篇译文所需字段。
- 结果继续区分 AI 生成、人工修订、注释包译文和许可清晰的开放译文。
- 缺少配置时提供进入 AI 设置的明确入口，不只显示底层错误。

### D5：数据管理分阶段开放

- 首版只提供安装精选合集、查看占用、更新和删除。
- 正文索引开关可复用，但移动端默认优先控制磁盘占用。
- 移动端不提供本地注释包或翻译包导入，避免额外的文件选择、格式兼容和错误恢复流程。
- 注释包放到后续阶段，只提供受控的在线安装、更新和删除。
- 注释包的版权边界维持现有方案：用户显式下载、不随安装包分发、可独立删除。
- 如果以后提供许可证清晰的开放译文，同样使用受控在线下载，不增加本地 JSON 导入入口。

## 6. 后端计划

### 6.1 精选文件同步

- [x] 桌面和移动端共用 GitHub tree/blob API，按 catalog 路径筛选所需正文文件。
- [x] 移动端不依赖桌面端，不依赖预处理资产或 GitHub Release 数据资产。
- [x] 移动端拒绝完整 tar.gz 回退；API 额度不足或请求失败时返回可重试错误。
- [x] 对下载文件执行路径匹配、临时目录隔离和现有解析校验。
- [x] 不拼接 SQL，继续使用现有参数化和事务导入。

### 6.2 桌面兼容路径

- [x] 桌面端保留上游 tar.gz 回退，用于 GitHub API 额度不足或 tree/blob 暂时不可用的场景。
- [x] 桌面端已有本地归档/目录导入能力；移动端不开放该入口。
- [ ] 真机验证移动端精选文件下载、取消、重试、低磁盘和切后台行为。

### 6.3 移动端下载与导入

- [x] 将移动端 tree/blob 下载逻辑接入共享 GitHub 同步模块，并保持独立运行。
- [x] 文件系统、网络和正文解析继续放在 Rust 后端。
- [x] 重活运行在 blocking 线程或独立任务，不阻塞 async runtime。
- [x] 进度继续通过 `library://sync-progress`，不新增内联事件名。
- [x] 临时文件写入应用数据目录下的专用临时目录。
- [x] 校验通过后再导入，事务成功后才更新合集版本。
- [x] 失败、取消和应用退出都有临时资源清理路径。
- [x] 启动时清理上次强制退出留下的临时下载/导入目录，保留已安装数据库。
- [ ] 低磁盘和真机网络场景验证。
- [x] 避免把 API Key、下载 URL 中的敏感参数或正文内容写入日志。

### 6.4 AI 翻译

后端原则上不新增第二套实现，只补移动端验证和必要的生命周期收口：

## 8. 测试矩阵

### 8.1 Rust

- tree/blob 路径筛选、API 额度不足和下载失败处理。
- 临时目录清理、文件路径约束、事务回滚和重复导入幂等。
- 下载取消、临时文件清理、事务回滚和重复导入幂等。
- uid 稳定、合集替换、旧数据保留与 schema 迁移。
- AI 凭据接口错误不会泄露 Key。
- AI 输入白名单、重复任务、流式完成和无效输出。

### 8.2 前端

- 空库、已安装、下载中、导入中、失败、取消和可更新状态。
- 搜索防抖、筛选、分页、返回恢复和滚动恢复。
- 详情加载、超长正文、无注释、无译文和多种译文来源。
- AI 未配置、生成中、生成失败、编辑、删除和覆盖确认。
- 软键盘、横竖屏、safe-area、动态字体和窄屏文案换行。
- 所有按钮、菜单、图标和表单控件有可访问标签。

### 8.3 平台

至少覆盖：

- iPhone 小屏和大屏模拟器，以及一台 iOS 真机。
- Android 小屏模拟器，以及一台 API 28 或更高真机。
- Wi-Fi、蜂窝网络、断网和受限网络。
- 应用前后台切换、锁屏、强制退出和重启。
- 有充足空间、接近空间上限和空间不足。

## 9. 验证命令

每个涉及用户文案的阶段：

```bash
pnpm run extract
pnpm run compile
pnpm build
pnpm lint
pnpm format:check
```

后端阶段：

```bash
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml --locked
```

移动目标和端到端验证：

```bash
pnpm ios:dev

```

提交前还需对所有新增和修改文件横切扫描：文件行数、前后端注释语言、硬编码用户文案、
事件名、直接 invoke、手写 IPC 类型和生成物差异。

## 10. 风险与对策

| 风险                       | 影响                   | 对策                                             |
| -------------------------- | ---------------------- | ------------------------------------------------ |
| 文件下载和临时导入占用     | 下载失败或系统清理进程 | 首版精选合集、安装前空间检查、大小上限、失败清理 |
| iOS 后台挂起               | 下载或导入中断         | 首版前台完成、状态可恢复、不承诺后台下载         |
| 上游文件缺失或被替换       | 导入错误或数据污染     | HTTPS、tree/blob 路径筛选、解析校验、事务导入    |
| 桌面双栏回归               | 已有用户体验下降       | 移动编排独立，保留共享数据层和桌面布局回归测试   |
| Keychain/Keystore 行为差异 | 无法保存或删除 Key     | iOS/Android 真机覆盖完整凭据生命周期             |
| AI 服务兼容性不同          | 流式解析或输出失败     | 保持 Responses 契约，覆盖流式/非流式，不静默降级 |
| 第三方服务费用与隐私       | 用户误触或内容外发     | BYOK、单篇主动点击、生成前提示、无批量入口       |
| 注释包版权边界             | 分发风险               | 仅受控在线安装、不进安装包、独立删除、延后到 M4  |

## 11. 完成定义

移动端首版只有同时满足以下条件才视为完成：

- [ ] iOS 和 Android 均可从空安装获取精选诗词数据。
- [ ] 浏览、搜索、详情、每日一诗和随机阅读可用。
- [ ] 返回列表保留查询、筛选和阅读位置。
- [ ] AI 设置、两种翻译模式、流式输出和译文管理可用。
- [ ] API Key 只存在于系统安全凭据库。
- [ ] 下载和导入失败不会损坏已安装数据或残留无界临时文件。
- [ ] 桌面端文库和 AI 翻译无行为回归。
- [ ] i18n、构建、Lint、Rust 测试和两端真机冒烟全部通过。
- [ ] 所有新增 Rust、TypeScript 和 TSX 源文件不超过 600 行。

## 12. 实施顺序结论

推荐顺序为 `M0 -> M1 -> M2 -> M3 -> M4`。M1 可以使用开发测试库先完成交互，
但不能在没有 M2 的情况下作为面向用户的移动端功能发布；否则全新安装没有数据来源。
M3 的后端基础已经完成，可与 M2 后半段并行开发，但最终必须在真实移动设备和真实用户自配
Responses 服务上完成验收。
